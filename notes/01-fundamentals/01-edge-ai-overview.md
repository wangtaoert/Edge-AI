# 第一讲：端侧 AI 的全景 - 从训练到部署，芯片在哪里？

> 目标：建立端侧 AI 的系统视角，明确模型从训练到部署的完整链路，搞清楚 NPU/HAL 代码在整条链路中的位置。

## 1.1 一个关键思维切换

对嵌入式开发者来说，最重要的切换是：

- NPU 本质上也是一个外设
- 只是它执行的不是“收发字节”，而是“卷积/矩阵乘”

运行时 CPU 主要做三件事：

1. 配寄存器
2. 触发 start
3. 等待 done

这意味着端侧 AI 驱动开发的核心不是训练算法，而是把“已训练模型”拆成硬件可执行的指令和参数。

## 1.2 模型的一生：从训练到芯片

```text
[云端训练]                    [部署工具链]                    [端侧芯片]
PyTorch/框架  ------->  量化/编译/打包  ------->  NPU 指令 + 权重 + scale
FP32 checkpoint         INT8/INT4 等格式            HAL 下发寄存器并执行
```

你在这条链路中的位置是最右侧：

- 输入：编译器已经算好的算子参数与内存地址
- 输出：一次次可执行的硬件寄存器写入序列

## 1.3 为什么不是 CPU/GPU，而是 NPU

端侧设备受三类硬约束：

- 功耗：电池供电，持续发热不可接受
- 成本：芯片面积和带宽预算有限
- 时延：交互任务需要毫秒级响应

NPU 通过“专用化”换能效：

- 弱化通用控制逻辑
- 强化矩阵乘和数据复用能力
- 配合量化降低存储与带宽压力

简化理解：NPU 用更少的通用性，换更高的 TOPS/W。

## 1.4 端侧 AI 的三座大山

### 山 1：内存墙

算得快不代表整体快。端侧常见瓶颈是搬运而不是计算。

- 现象：PEA/算力单元空转等数据
- 对策：片上 SRAM + 分块 + ping-pong + 算子融合

### 山 2：精度与成本平衡

FP32 精度高但代价大，INT8/INT4 更省资源但有精度损失。

- 现象：位宽降低后误差放大
- 对策：分层策略（敏感层高精度，非敏感层低精度）

### 山 3：功耗

端侧工程的核心不是“跑起来”，而是“稳定可用地跑起来”。

- 现象：高带宽访问导致能耗飙升
- 对策：尽量片上完成中间处理，减少 DDR 往返

## 1.5 从工程视角看“芯片在哪里”

如果把端侧 AI 看成一条生产线：

1. 训练：云端高算力得到模型权重
2. 量化：压缩表示以适配端侧资源
3. 编译：将计算图映射为目标芯片可执行计划
4. Runtime：调度算子、管理内存和同步
5. HAL/Driver：把计划翻译为寄存器配置
6. 芯片执行：DMA + 计算阵列 + 向量单元 + 同步控制

“芯片在哪里”的准确答案是：

- 芯片在最后执行端
- 但芯片能力真正被发挥，依赖前面四层软件栈

完成第一讲后，你应该能回答这 4 个问题：

1. 端侧 AI 和云端 AI 的主要工程差异是什么？
2. 为什么端侧常常是 memory-bound 而不是 compute-bound？
3. 量化在端侧部署里解决了什么问题，又引入了什么问题？
4. 训练、编译、Runtime、HAL、NPU 各自职责边界是什么？

## 1.8 作业参考答案

### 题 1：5 句话解释“模型从训练到芯片执行”的完整路径

1. 模型先在云端用 FP32 训练得到权重和网络结构。
2. 部署前通过量化把模型压缩为 INT8/INT4 等低位宽表示，并生成 scale 等参数。
3. 编译器把计算图映射为目标芯片可执行的算子序列、分块策略和内存地址计划。
4. Runtime 在端侧按顺序调度算子，准备输入输出缓冲区并管理同步。
5. HAL 把每个算子的参数写入寄存器并启动 NPU，硬件完成 DMA 搬运、计算和结果回写。

### 题 2：各举 1 个例子说明“算力不是瓶颈”和“带宽才是瓶颈”

- 算力不是瓶颈的例子：小 batch 的 LLM decode 阶段，矩阵规模偏瘦长，MAC 阵列利用率不高，很多计算单元在等待数据。
- 带宽是瓶颈的例子：频繁从 DDR 读取权重和 KV cache，即使 NPU 理论 TOPS 很高，整体时延仍主要由内存搬运决定。

### 题 3：类比一次 NPU 任务调度过程（嵌入式视角）

可把 NPU 看成一个复杂外设，流程类似“配置 DMA 的外设传输任务”：

1. CPU 根据算子描述符配置寄存器（源地址、目标地址、数据格式、分块参数）。
2. 触发 start 后，DMA 先搬输入和权重到片上 SRAM。
3. 计算阵列开始执行卷积或矩阵乘，VCU 同时处理激活、归一化等向量算子。
4. 任务完成后硬件置位 done 或触发中断，CPU 读取状态并下发下一算子。
5. 整个模型执行就是“配置-启动-等待-切换下一任务”的循环。
