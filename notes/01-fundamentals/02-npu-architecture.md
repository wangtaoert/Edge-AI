# 第二讲：NPU 内部架构详解 - PEA、VCU、DMA 怎么配合

> 目标：从“知道 NPU 是什么”升级到“知道 NPU 如何跑起来”。看完本讲，你应能读懂大多数 HAL 接口背后的硬件意图。

## 2.1 先看全貌：NPU 的执行闭环

NPU 常见执行闭环可以抽象为：

```text
DDR <-> DMA <-> 片上 SRAM <-> PEA/VCU <-> DMA <-> DDR
				 ^
				 | 由控制/同步单元编排阶段和依赖
```

关键点：

1. 数据总是先被搬运，再被计算。
2. 计算单元很快，真正难的是让它持续“吃到数据”。
3. 性能优化本质上是调度优化：让搬运和计算尽量并行。

## 2.2 SRAM：NPU 的工作台

片上 SRAM 是性能关键，不是可选项。

常见分区：

- ifmap buffer：输入特征图
- weight buffer：权重
- psum buffer：部分和
- scale/LUT buffer：量化 scale、激活查表

为什么 SRAM 重要：

- 访问延迟和能耗远低于 DDR
- 能支持高频重复访问（数据复用）

工程实践上，SRAM 编排通常比算子数学本身更影响最终时延。

## 2.3 PEA：矩阵乘和卷积主力

PEA（Processing Element Array）负责大头算力工作：

- GEMM（矩阵乘）
- CONV（卷积，通常映射为矩阵乘变体）

你需要抓住两个概念：

### 1) 分块（Tiling）

完整矩阵往往放不下 SRAM，必须拆成 tile。常见参数如：

- tile_m
- n_groups
- k_groups

其本质是“空间换时间”：牺牲调度复杂度，换取可执行性和更好复用。

### 2) 部分和累加（Psum Accumulation）

当 K 维被拆分时，每次计算只得到部分和，需要跨阶段累加：

- 首次：覆盖写
- 后续：累加写

如果累加策略错，结果就会系统性偏差。

## 2.4 VCU：所有非矩阵乘的高频算子

VCU（Vector Computing Unit）承担：

- 激活：ReLU、Sigmoid、GELU 等
- 池化/上采样/转置
- 归一化及部分 LLM 专用算子

典型设计特点：

1. 查表近似（LUT）
2. 指令序列化执行（opcode 链）
3. 与 PEA 配合做算子融合

为什么要 LUT：

- exp、tanh、rsqrt 等函数直接硬算代价高
- 查表 + 插值是面积和精度的工程折中

## 2.5 DMA：被低估但最关键的主角

DMA 不只是“拷贝数据”，而是“按张量布局做多层循环搬运”。

你会看到 iteration_2/3/4 这类接口，它们对应的是：

- 二层、三层、四层嵌套搬运模式

为什么要分层：

- AI 数据是多维张量，不是简单线性数组
- 需要 stride、hop、burst 的组合来表达稀疏或分块搬运

一个实用判断：

- 线性连续搬运：较低层 iteration 即可
- 复杂 layout 或高维切片：需要更高层 iteration

## 2.6 控制与同步：把模块变成流水线

仅有 PEA/VCU/DMA 还不够，必须用同步机制把它们“编排成舞”。

常见控制逻辑：

1. 配置阶段依赖（谁等谁）
2. 指定每阶段各引擎执行哪条指令
3. 启动、等待、清状态

目标不是“能跑完”，而是“流水线跑满”：

- load 下一块数据时，上一块应在计算
- 计算当前块时，上一块可在做激活或回写

## 2.7 Ping-Pong 缓冲：并行化基本功

Ping-pong 的核心是双缓冲：

```text
时刻 T0: DMA 写 A, 计算读 B
时刻 T1: DMA 写 B, 计算读 A
时刻 T2: DMA 写 A, 计算读 B
```

收益：

- 减少计算单元等待搬运
- 平滑总线突发带来的抖动

注意：如果 DDR 带宽本身已是绝对瓶颈，ping-pong 只能部分缓解，不能根治。

## 2.8 为什么端侧常是 memory-bound

第二讲的核心结论是：

- 大多数端侧推理性能问题，最终都落到内存系统

典型症状：

1. 理论 TOPS 很高，实际吞吐不达标
2. profile 里 DMA 时间占比显著高于计算时间
3. 算子融合后收益明显大于单纯提高主频

典型优化优先级：

1. 降低数据搬运量（量化、融合、复用）
2. 提升 SRAM 命中和复用
3. 最后才是提升纯计算吞吐

## 2.9 本讲小结

你应该已经建立以下心智模型：

1. NPU = 数据搬运系统 + 计算系统 + 同步系统
2. PEA 决定峰值算力，DMA 决定能否接近峰值
3. VCU 提供非矩阵算子的完整性与融合能力
4. 端侧优化的本质是“调度和访存”而非“公式推导”
